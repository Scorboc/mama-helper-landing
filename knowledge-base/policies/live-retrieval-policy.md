# Правила интернет-поиска для чата

Пользователь прав: чат может обращаться к интернету, когда внутренней базы недостаточно или материал мог устареть. Но это не «поиск в Google и пересказ первой страницы».

## Когда разрешён поиск

Только если одновременно выполнены условия:

1. В утверждённой базе нет подходящей карточки, либо её дата проверки истекла, либо пользователь явно просит актуальный организационный факт.
2. Вопрос не содержит красный флаг и не требует немедленной помощи.
3. Поиск ограничен доменами из `source-registry.json` и конкретными источниками, утверждёнными редактором.
4. Из найденного документа можно установить автора, дату/версию и применимость.

## Когда поиск запрещён

- при симптомах с красным флагом: сначала экстренный маршрут, без ожидания поиска;
- для подбора доз, лекарств, лечения, лечебной гимнастики и индивидуального диагноза;
- по форумам, соцсетям, блогам, отзывам и маркетплейсам;
- для поиска персональных данных, «лучшего врача», частных контактов или чужих медицинских историй;
- если вопрос содержит идентифицирующие данные ребёнка или медицинские документы — сначала предложить их не отправлять.

## Алгоритм

1. Нормализовать вопрос и определить тему, возраст/срок и уровень риска.
2. Найти утверждённые карточки по теме и версии источника.
3. Если карточки достаточно — отвечать только по ней.
4. Если недостаточно — выполнить ограниченный поиск в allowlist, получить максимум несколько первичных документов.
5. Проверить дату, автора, противоречия и применимость. Не использовать текст из результата автоматически как знание.
6. Дать осторожный краткий ответ с внутренней записью происхождения. Если ответ влияет на лечение или есть неопределённость — направить к специалисту.
7. Поставить найденный материал в очередь `medical-review`, а не публиковать его в постоянной базе автоматически.

## Технические ограничения

- Один отдельный сервис `retrieval` имеет право ходить в интернет. Модель и браузер пользователя не получают произвольный URL.
- Разрешённые домены и пути проверяются на сервере до запроса; редиректы повторно проверяются.
- Запросы не содержат имя, контакты, точную дату рождения, медицинские документы или полный текст личной переписки.
- В журнал попадают только: тема, версия источника, причина поиска, ID карточки, статус проверки. Медицинский текст пользователя не пишется в аналитический лог.
- Ответ сохраняет `source_ids` и `knowledge_version`; это нужно для аудита и отзыва карточки после обновления источника.

## Псевдокод маршрута

```text
if red_flag(question, profile): emergency_route()
else if approved_card_matches(question, profile): answer(card)
else if safe_to_search(question) and allowlisted_source_exists(topic):
    retrieve_allowlisted_source(); answer_with_limits(); queue_medical_review()
else: explain_uncertainty_and_refer()
```
