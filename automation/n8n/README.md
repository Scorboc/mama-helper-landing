# Локальная автоматизация MAMA

Анализ отзывов через ИИ подключён локально: [процесс и границы](FEEDBACK_ANALYSIS.md).
Это отдельный `mamaLocal19`; прежние ежедневные и недельные отчёты сохраняются.

Панель: http://127.0.0.1:5678/home/workflows

Доступ владельца хранится в `private/n8n/owner-access.txt`. Не публикуйте этот файл, настройки и ключи.

## Работает

Локальные расписания, время Саратова (Europe/Saratov):

1. Проверка сайта, сервиса аккаунтов и n8n каждые 5 минут.
2. Зашифрованная резервная копия ежедневно в 02:15.
3. Ежедневный отчёт в 08:00.
4. Недельный обзор и задания администратору по понедельникам в 09:00.
5. Проверка восстановления последней копии ежедневно в 03:00.
6. Регрессии правил ИИ ежедневно в 09:30, без платных вызовов модели.

Первый этап: результаты CLI-проверок и регрессий в outputs/n8n-phase1-20261013/. Реальное срабатывание каждого расписания в соответствующее время и запуск после перезагрузки отдельно не проверены.

Отчёты: `private/n8n/reports/`. Проверки: `private/n8n/monitor.json`. Состояние процессов: `private/n8n/status.json`.

Отчёты используют агрегированные показатели и правила, без платных запросов ИИ. Индивидуальные переписки не отправляются наружу. Предложения содержат задание для администратора; автоматического изменения кода и медицинских инструкций нет.

## Резервные копии

Архивы в `private/n8n/backups/` включают согласованные копии баз аккаунтов, операций, бюджета ИИ и n8n, настройки и исходники. Проверяются целостность SQLite и шифрование. Ключ `private/n8n/backup.key` хранится отдельно от архивов: сохраните его безопасную копию, иначе архивы не расшифровать. Полное восстановление на другом компьютере ещё не проверено.

## Независимый запуск

Скрытый watchdog запускает недоступные локальные службы и обновляет статус каждые 20 секунд. Настроен автозапуск при входе текущего пользователя Windows. Пока watchdog работает, предотвращается автоматический сон компьютера. После выключения компьютера задания не выполняются. Реальная перезагрузка не проверена.

## Требуют подключения

Схемы с пометкой «НУЖНО ПОДКЛЮЧЕНИЕ» — явно обозначенные заготовки проверки готовности, не работающие интеграции. Нужны Telegram-бот и ID администратора, SMTP, платёжный сервис и обработка чеков самозанятого, Instagram, провайдер анализа ИИ и согласованные интерфейсы сайта. Оплата, возвраты, налоги, публикации и изменение правил не выполняются автоматически.

Облачная схема `cloud-safe-operator.json` проверена на искусственных агрегатах. Она не подключена к реальным данным сайта и не обращается к платной модели. Старый облачный workflow сохранён в частной резервной копии.

## Надёжность — первый этап

Задания используют Idempotency-Key из ID схемы и исполнения. Успешный повтор возвращает сохранённый результат; параллельный запрос, повтор неуспешной операции или операции с неопределённым результатом получает 409. При перезапуске моста незавершённые записи помечаются uncertain. Проверьте предыдущий результат перед новым запуском. Ручной повтор исполнения в n8n создаёт новый ID и считается новым запросом. Для будущих платежей потребуется отдельный ID события провайдера.

Журнал: private/n8n/automation-journal.sqlite. Error Trigger сохраняет только ID схемы и исполнения, без текста ошибки, исходных данных или переписки. Доставка проверяется фоновой намеренной ошибкой; тестовое расписание затем отключается. При недоступном мосте локальная доставка может не состояться, но исходная ошибка остаётся в Executions n8n. Telegram не подключён.

Восстановление: последняя копия расшифровывается в отдельную временную папку; сверяются SHA-256, integrity_check и количество строк по таблицам. Рабочие базы не заменяются. Результат: private/n8n/restore-status.json. Полное восстановление на другом компьютере не проверено. Архив теперь включает журнал автоматизации.

ИИ: синтетические регрессии возраста, поддержки, активного профиля, свежести дневника, лимитов и автоматизации. Ключи удаляются из окружения дочернего процесса; соединения вне localhost запрещены; тестовые базы изолированы. Отчёт: private/n8n/reports/ai-regression-latest.json и .log. Отчёт содержит дату и хеш исходников. Падение теста вызывает ошибку процесса n8n. Новые ответы реальной модели этим этапом не проверяются.
