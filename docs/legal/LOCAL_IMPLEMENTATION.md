# Локальная реализация платного доступа

## Что работает в коде

- По умолчанию `APP_BILLING_MODE=paid`. Тариф фиксирован на сервере: 480 ₽, календарный месяц, общий лимит 300 успешных ответов/подборок/замен ИИ на аккаунт.
- Даты окончания — календарный месяц с ограничением последним днём следующего месяца. Новая покупка допускается после окончания текущего периода. Автопродления нет.
- `mh_paid_access` и прежние подарки сохранены. Бесплатный доступ назначается отдельной записью `mh_test_access` только через панель владельца. Активная выдача/продление теста не сбрасывает расход; отозванный тест не удаляет историю.
- ИИ-подборка из нескольких занятий расходует одну единицу; кэш и каталог её не расходуют. Подарочные ответы остаются для чата. Ошибки не уменьшают лимит. В конце лимита ежедневные новые игры работают из каталога; замена с анализом причины требует ИИ-лимита.
- API сверяет права, редакцию оферты, сумму и валюту на сервере. Перед сетью сохраняет заказ и ключ идемпотентности. Статус возвращения браузера и присланный webhook не являются подтверждением оплаты: выполняется авторизованный GET у провайдера. Дубликат не начисляет доступ повторно. Чужой заказ недоступен.
- Адаптер ЮKassa создан, но не подключён. В локальной конфигурации платежи принудительно отключены. Все проверки оплаты проводились с имитацией API, без реальных списаний.
- Условия и оферта принимаются отдельно; хранятся версия, время, хеш и снимок документа с реквизитами. Они не названы согласием на здоровье. Старые пользователи не получают фиктивное новое согласие.
- Обращения и их результаты шифруются; владелец рассматривает их локально. Экспорт проверяет текущий пароль и исключает пароли, токены и коды. Запрос прекращения/удаления создаёт запрет новых вызовов ИИ; отметка рассмотрения не снимает запрет автоматически.
- После удаления аккаунта финансовый заказ сохраняется без ссылки на пользователя для проверки платежа/возврата; он не привязывается к повторной регистрации. Обращения могут сохраняться по своему законному основанию. Сроки и очистку ещё нужно утвердить.

## Как вручную выдать бесплатный тест

1. Открыть панель владельца: `http://127.0.0.1:8791/#access`.
2. Ввести существующую почту/логин, срок и лимит. По умолчанию 30 дней и 300 единиц.
3. Нажать «Применить к выбранному аккаунту».
4. Пользователь обновляет страницу кабинета. Для отзыва — тот же логин и отметка «Отозвать бесплатный доступ».

Автоматически бесплатные аккаунты владельца, `test01–test50` и новые пользователи не назначались. Существующие действующие оплаченные права не изменяются.

## Конфигурация будущего сервера

Для публичного режима дополнительно введена индивидуальная проверка `mh_health_consents`: без проверенного подписанного согласия персональная запись/анализ и покупка полного доступа закрыты. Записи не создаются из галочки пользователя. Процедура получения и проверки подписи ещё не реализована; пустая таблица не выдаёт разрешений. Локальный режим предназначен для разработки и синтетической проверки и обходит эту публичную проверку. Не разворачивать `APP_LOCAL=1` на публичном сервере.

Публичные реквизиты: `APP_OPERATOR_NAME`, `APP_OPERATOR_INN` (12 цифр), `APP_OPERATOR_ADDRESS`, `APP_SUPPORT_EMAIL`. Размещение первичной базы: `APP_DATA_COUNTRY=RU`. `APP_PUBLIC_URL` — HTTPS адрес своего сайта. `APP_LEGAL_APPROVED=1` — только после выполнения юридического перечня; флаг не является доказательством согласий или юридической готовности.

Платёжные секреты: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`; только защищённые настройки. `APP_PAYMENTS_ENABLED=1` — после тестов и утверждения документов. `APP_PAYMENTS_TEST=1` — только для тестового магазина; реальный магазин принимает только нетестовые подтверждения.

Nginx должен проксировать `/payment-notification` на `127.0.0.1:8787/payment-notification`; в ЮKassa указать этот HTTPS адрес и события `payment.succeeded`, `payment.canceled`. Подлинность проверяется повторным запросом объекта: [документация](https://yookassa.ru/developers/using-api/webhooks). Локальный адаптер на 8787 предназначен для проверки приложения, а не публичных webhooks; будущий сервер использует `production_server.py`.

Нужна отдельная регулярная сверка незавершённых заказов с провайдером, мониторинг доставки уведомлений, оформление НПД-чеков и регламент возвратов. Автоматическая сверка и налоговая интеграция не включены этой реализацией. Нельзя считать платёжный запуск завершённым по одной проверке сборки.

## Что ещё не готово к публичному запуску

Реальные реквизиты и утверждённая политика с фактическими сроками и обработчиками; надлежащая индивидуальная подпись согласий на здоровье; проверенный российский сервер; подтверждённые уведомления РКН; реальный SMTP; тестовый/рабочий магазин; выдача чеков НПД; настоящий возврат; регламент уничтожения резервных/внешних копий и его подтверждения; плановая очистка служебных записей; проверка защиты и медицинского назначения.

Не включать приём данных/денег до закрытия применимых пунктов. Все прежние данные сохранены; массового удаления или изменения профилей нет.
