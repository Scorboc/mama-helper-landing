## Быстрый статус передачи

Проект передаётся как существующая рабочая тестовая система. Код, VM, backend,
frontend, возрастные правила, сохранение профилей и диалогов, 50-вопросный тест,
резервные копии и базовые проверки уже сделаны.

До публичного запуска остаются обязательные задачи:

1. Принять доступы владельца через защищённый канал.
2. Проверить актуальный AI-провайдер и лимиты после получения ключа.
3. Проверить реальную доставку Web Push на телефоне и браузере.
4. Подключить настоящий домен и HTTPS, если сайт будет публичным.
5. Утвердить политику обработки персональных данных, реквизиты оператора,
   сроки хранения и порядок удаления данных.
6. Пройти финальный smoke-тест на чистом тестовом аккаунте и сделать backup.
7. Только после этого открыть регистрацию реальным пользователям.

Текущий адрес `sslip.io` — тестовый адрес по IP, а не окончательный домен бренда.

## Что ещё не считается подтверждённым

- Реальная доставка Web Push на внешнем телефоне; активная служба сама по себе её не подтверждает.
- Нагрузка на 1000 одновременных пользователей.
- Медицинская экспертиза всех редакционных текстов.
- Настоящий домен, почтовая верификация и платежи.
- Старый Poehali-контур не отключать до финальной проверки и резервного копирования.

## 1. Что это за проект

«Мамин помощник» — веб-приложение для родителей. В нём есть:

- регистрация, вход и восстановление по одноразовому коду;
- профиль родителя и отдельные профили нескольких детей;
- блокировка заполненного профиля ребёнка: после первого заполнения можно менять только имя, нового ребёнка добавляют отдельным профилем;
- чат с ИИ, поддержка мамы и сохранение диалогов;
- «Мой день»: отдельный совет для мамы и подборка занятий для ребёнка;
- возрастные советы, уход и гигиена, советы педиатров, первая помощь;
- избранное, 50-вопросный тестовый диалог и история сообщений;
- Web Push, день рождения ребёнка и не более двух уведомлений в день;
- PDF-инструкция для пользователя;
- тёмная/светлая тема и мобильная версия.

Для рекомендаций действует обязательное правило: каждый совет сверяется с точным полным возрастом активного ребёнка, нижней и верхней границей применимости, навыками, ограничениями и текущим вопросом. До двух лет подборка отдельная для каждого месяца. После двух лет — максимум два соседних месяца. Возрастной диапазон — период подбора, а не обязательный срок освоения навыка. Медицинские процедуры и массаж автоматически по возрасту не назначаются.

Источник правил: `CONTENT_RULES.md` и `AGENTS.md` в корне проекта.

### Обязательные доступы

1. **GitHub** — доступ Collaborator к репозиторию `Scorboc/mama-helper-landing`.
2. **Yandex Cloud** — доступ к облаку `momhelper`, VM и Cloud Shell. Для обычной работы достаточно OS Login; пароль Linux не нужен.
3. **Доступ к DNS/домену**, если будет подключаться настоящий домен вместо временного `sslip.io`.

### Доступы, которые выдаются только при необходимости

- **ProxyAPI** — отдельный API-ключ проекта, если текущая модель обслуживается через ProxyAPI.

- **VAPID** — серверные `VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT` для push.

Перед передачей любого API-ключа владелец должен создать отдельный ключ проекта с минимальными правами, сроком действия и возможностью отзыва. После завершения работ ключ отозвать или заменить.

### Что не нужно передавать

- пароль от личной почты владельца;
- пароль от аккаунта Yandex Cloud;
- приватный SSH-ключ владельца;
- секреты из `/etc/mama-helper.env` и `/etc/mama-helper-proxyapi.env` целиком;
- cookies браузера, recovery-коды пользователей и выгрузки базы.

Если доступ нужен, владелец сам вводит его в защищённом окне или выдаёт временный отдельный доступ.

## 5. Пошаговый запуск для нового программиста

1. Принять приглашение GitHub и клонировать репозиторий.
2. Прочитать `AGENTS.md`, `CONTENT_RULES.md`, `DEPLOYMENT.md` и этот документ.
3. Открыть VM через Yandex Cloud Cloud Shell с OS Login.
4. Проверить рабочие пути backend `/opt/mama-helper-yandex/releases/20260919-1425-yandex/backend/parent-app` и frontend `/var/www/mama-helper/current`.
5. Сделать backup базы и файлов до любых изменений.
6. Проверить закрытые переменные окружения без вывода их значений.
7. Запустить тесты и сборку из раздела 9.
8. На чистом тестовом аккаунте проверить регистрацию, вход, recovery, профиль,
   второго ребёнка, чат, «Мой день», избранное, первую помощь и PDF.
9. Проверить возраст 0, 3, 6, 12, 13, 14, 18, 24, 36, 60, 72 и 84 месяца,
   неизвестный возраст и беременность.
10. На телефоне владельца проверить разрешение push, первое уведомление, второе
    только при настройке, лимит двух уведомлений и переход в чат.
11. При подключении домена настроить DNS, HTTPS, same-origin `/api`, cookies и SPA-fallback.
12. Сделать финальный backup и записать номер выпуска и результаты тестов.
13. Открыть публичную регистрацию только после подтверждения владельца.

## 6. Серверные секреты и переменные

Секреты уже хранятся на VM в закрытых файлах окружения. Их значения не печатать:

- `APP_DATA_KEY` — шифрование профилей, переписок и push-подписок;
- `APP_ORIGINS` — точные HTTPS-origin сайта;
- `APP_DB_DRIVER=sqlite` и путь SQLite для текущей одной VM;
- AI-переменные выбранного провайдера: `CHEAPAI_API_KEY`/совместимое имя либо `YANDEX_FOLDER_ID`, `YANDEX_API_KEY`, `YANDEX_MODEL`;
- `VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT`;
- `REMINDER_JOB_TOKEN`.

Не задавать `APP_LOCAL` в production. Не помещать секреты в `VITE_*`, `public/app-config.json`, frontend или GitHub. При потере `APP_DATA_KEY` зашифрованные данные прочитать нельзя, поэтому резервную копию ключа хранить отдельно от базы.

## 8. Данные, приватность и безопасность

Профили, переписки и push-подписки шифруются на сервере. Пароли хранятся как PBKDF2-SHA256-хеши, сессии — в HttpOnly cookies. Email используется для входа.

Для разработки использовать только вымышленные данные детей. Не выгружать переписки, медицинские сведения или тестовые логины в сторонние сервисы. Историю существующих аккаунтов не переписывать и не смешивать профили детей.

До публичного запуска отдельно утвердить операторские реквизиты, политику обработки данных, сроки хранения и порядок удаления данных.

## 9. Проверка перед передачей результата

Минимальный набор:

```text
TypeScript: node node_modules/typescript/bin/tsc --noEmit
Build:      node node_modules/vite/bin/vite.js build
Backend:    python -m unittest discover -s backend/parent-app -p "test_*.py"
```

Обязательно проверить:

- регистрация → recovery-код → вход → профиль → выход → повторный вход;
- невозможность увидеть данные другого аккаунта;
- блокировку заполненного профиля и добавление второго ребёнка;
- ответ чата с точным возрастом и без повторного призыва «написать в чат»;
- помесячные карточки на 13, 14, 24 и 72 месяцах;
- «Мой день» на активном ребёнке;
- избранное, PDF-инструкцию и старый диалог из 50 вопросов;
- Web Push и ограничение до двух уведомлений в день;
- резервную копию и восстановление на тестовой копии.

Не считать модель ИИ безошибочной только потому, что системная инструкция загружена: возрастные границы, ограничения и fallback должны проверяться программно.

## 10. Правила работы программиста

Не менять провайдера ИИ, домен, схему базы, лимиты, тексты медицинских советов, push-расписание или доступы без записи причины и проверки владельцем. Любое изменение, затрагивающее данные, сначала тестируется на копии. После каждого выпуска указывать номер выпуска, резервную копию и результаты тестов.

Пароли передаются владельцем отдельно, одноразово или через менеджер секретов. В этой инструкции перечислены только названия доступов и места их применения — это сделано специально для защиты аккаунтов и пользовательских данных.
