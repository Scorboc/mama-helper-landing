## Браузерные действия

1. Настоящая регистрация в изолированном API, сохранение сессии.
2. Заполнение профиля один раз и возвращение в чат.
3. Начало/окончание сна, кормление, утренний подъём, заметка; все записи в одном серверном дневнике.
4. Потеря ответа после серверного сохранения: повтор с тем же ID, в дневнике ровно одна запись.
5. Экран 375×812, горизонтальный 812×375 и планшет 768×1024: нет горизонтального переполнения, высота быстрых кнопок ≥44 CSS px.
6. Поле вопроса и ссылка на срочную помощь видны над нижней навигацией, включая увеличенный базовый размер текста.
7. Светлая/тёмная темы и reduced motion; снимки просмотрены вручную. При большом тексте сетка быстрых действий переходит в одну колонку без разрыва слов.
8. «Графики» → существующие трекеры → «К врачу» → настоящий скачанный TXT с проверкой содержимого.
9. Ошибка загрузки дневника: кнопки записи отключены, повтор восстанавливает доступ.
10. Срочный вопрос «Ребёнок не дышит»: ответ с 112 без вызова внешней AI-модели.
11. Публичная страница первой помощи.

Отчёт браузера: `../../outputs/qa-v3/browser-results.json`. Снимки: `../../outputs/qa-v3/phone-light.png`, `phone-dark.png`, `phone-large-text.png`, `landscape.png`, `tablet.png`. В них только вымышленные тестовые сведения. Секрет регистрации не снимался и не выводился.

## Воспроизведение

Из `app/`, с Python, содержащим cryptography, tzdata и Playwright, и установленным Chrome:

```text
python scripts/qa-run-jtbd.py
```

Скрипт проверяет свободные порты 5173/8787, запускает собственный временный API без платных AI-вызовов и Vite, затем останавливает только собственные процессы. При необходимости путь к Node задаётся `MAMA_QA_NODE`. Тестовый API не подменяет рабочую базу.

Сервер:

```text
python -m unittest discover -p "test_*.py"
```

Рабочая папка серверных тестов — `backend/parent-app`.

## Что не доказано этой проверкой

- Ответ и задержка реального внешнего AI-провайдера. В серверных тестах используется тестовый ответ, а браузер проверял лишь срочный локальный маршрут и работу дневника.
- Push на устройстве, фоновое расписание и VAPID; никакая новая подписка на уведомления не создавалась.
- Оплата, автоматические списания, налоги: интеграции не подключались.
- Производственный сервер и точное совпадение с VM/альтернативным Worker.
- Медицинская корректность всех возможных ответов, полноценный аудит WCAG и поведение клавиатуры/VoiceOver на реальном iPhone.
- Холодная загрузка без интернета. Ошибки сервера проверены; это не обещание полной автономной работы сайта.

Изменения не опубликованы. Существующая проблема размера сборки остаётся отдельной задачей; её исправление потребует проверки разделения маршрутов и загрузки библиотек.
