# Telegram → правки владельца → чат MAMA → GitHub

Обновлено 18.10.2026. Основное приложение сохраняется; отдельные дизайн-прототипы
и старые preview-room/ не входят в эту автоматизацию.

## Два способа работы

- `/task <описание>` — прежний отдельный локальный исполнитель Codex. Его сообщения
  не появляются автоматически в открытом чате. Резервная копия, отдельная копия
  исходников, сборка, синтетические тесты и проверка конфликтов сохраняются.
- Новый путь — предложение бота, полная редакция владельца, просмотр промпта,
  `/send ID`, приём в явно выбранном чате MAMA, работа и результат в Telegram.

## Как пользоваться новым путём

1. Бот присылает агрегированный отчёт и предложение с ID вида `R012345abcdef`.
   Сигнал отчёта не объявляется доказанной ошибкой. Причины проверяются в работе.
2. Ответьте на сообщение с предложением полной редакцией задачи. Либо отправьте
   `/revise R012345abcdef <полный текст того, что нужно сделать>`.
3. Бот покажет промпт с вашей редакцией. Повторный `/revise` заменяет задачу целиком.
   Правка уже отправленного Telegram-сообщения тоже обновляет черновик. Правка
   сообщения `/send`, `/task` или `/publish` не запускает исполнение заново.
4. `/send R012345abcdef` ставит именно показанную редакцию в очередь чата MAMA.
   Редакция после отправки зафиксирована; повтор `/send` не создаёт второй запуск.
5. Чат отдельно подтверждает приём, проверяет наблюдение, выполняет работу и
   записывает результат, который бот доставляет владельцу.

`/reviews` показывает последние предложения; `/review ID` — подробности.
`/cancel_review ID` отменяет ещё не принятую задачу, сохраняя историю. Эта команда
не выдаётся за остановку уже выполняющейся работы.

## Как устроена передача в этот чат

`telegram_reviews.py` хранит отчёты, редакции, статусы и результат в существующей
защищённой локальной базе очереди Telegram. Отдельная автоматизация Codex в
выбранном чате проверяет очередь примерно раз в пять минут. Это локальная
очередь и штатный планировщик Codex, а не недокументированный API рабочего стола.

Получение задания в этом чате требует работающего компьютера, Codex и разрешённого
планировщика. Telegram-команды обрабатывает существующая схема n8n. Когда компьютер
выключен, задания не исполняются. Команды Telegram проверяются примерно раз в
10 секунд; передача в чат MAMA — раз в пять минут. Это разные этапы, не обещание
мгновенного выполнения задачи. Используются лимиты подписки Codex; отдельный
платный API для составления промпта не вызывается.

Локальная конфигурация `private/n8n/chat-handoff-settings.json` содержит только
включение и ID выбранного чата. Она не публикуется. Команды CLI получателя:

```powershell
python app/backend/parent-app/telegram_reviews.py --root private/n8n --thread <ID> pending
python app/backend/parent-app/telegram_reviews.py --root private/n8n --thread <ID> claim --id <R_ID>
python app/backend/parent-app/telegram_reviews.py --root private/n8n --thread <ID> finish --id <R_ID> --result "Проверенный результат"
```

`claim` атомарный: другой чат, отмена, повтор или уже принятая задача отклоняются.
Прерванное состояние `running` требует разбора, автоматического повторного
применения нет. Успешная отправка Telegram и успешный приём чатом — разные статусы.

## Публикация исходников в GitHub

Разрешён единственный репозиторий `Scorboc/mama-helper-landing`, ветка `main`.
`private/n8n/github-publication-settings.json` включает этот адрес локально.
Включение само по себе не публикует текущую папку, данные или будущие версии.

Для проверенного результата старого `/task` используйте `/publish T123`.
Бот проверяет `applied`, успешную сборку, ненулевое количество тестов, разрешённые
пути, отсутствие распознаваемых ключей и совпадение текущих исходников с проверенным
снимком. В очередь чата передаётся неизменяемый снимок конкретных файлов. Получатель
вызывает `telegram_publication.py`, затем записывает результат через `finish`.

Публикация сравнивает исходники на GitHub с базой задачи, сохраняет предыдущий commit
и выполняет обычный fast-forward push. Конфликт удалённых правок останавливает работу.
Нет force push, удаления файлов, переписывания истории или неограниченного git add.
Ошибочная/прерванная попытка не повторяется автоматически.

В новом пути после работы в чате публикация выполняется только при прямом разрешении
владельца на конкретный результат. Сообщать commit и фактические проверки обязательно.
Push исходников в main не означает обновление GitHub Pages, серверного API,
аккаунтов, почты или оплат. Эти системы проверяются отдельно.

## Данные и границы

- Отчёты строятся из разрешённых агрегатов, без вопросов, ответов и анкет родителей.
- Не присылайте в Telegram медицинские сведения, переписку, пароли или ключи.
  Регулярное выражение ловит некоторые секреты, но не является полной DLP-проверкой.
- Команды принимает только настроенный личный аккаунт; пересланные команды игнорируются.
- Промпт не является командой оболочки. Telegram-обработчик не запускает модель,
  git push, платёж или произвольный shell.
- Существующая зашифрованная копия включает базу Telegram и локальные настройки
  маршрутизации; восстановление не выполняется поверх рабочих баз во время теста.
- Поле `synthetic` явно маркирует тест, чтобы не исправлять выдуманную ошибку сайта.
