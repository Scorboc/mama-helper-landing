# Возрастные push: исправления и проверка

12 октября 2026. Основное приложение `app/`, только локальная версия.

## Исправлено

1. Отправитель проверяет согласие, подписку, выбранный час, семейный предел и
   предыдущую попытку до подготовки подборки. Отключённый push не вызывает ИИ.
2. Для локальной фоновой отправки используются проверенные возрастные карточки
   каталога. Платных вызовов ИИ этот процесс не делает. Создание и замена занятий
   по запросу в приложении сохраняют существующие лимиты и контроль расходов.
3. Одинаковая успешно принятая push-сервисом тема не выбирается повторно.
   После ошибки тема остаётся доступной на следующий день. Текущая попытка занимает
   свой слот даже при неоднозначном тайм-ауте, чтобы не отправлять дубликат сразу.
   Принятие push-сервисом не подтверждает показ на устройстве. При ошибке после
   фактического принятия доставка на следующий день теоретически может повториться.
4. Истёкшие подписки удаляются при 404/410; другие ошибки не удаляют подписку.
5. Из текста на экране блокировки исключены имя, дата рождения и сведения о
   здоровье. В ссылке остаются идентификатор профиля и тема. Важное действие по
   безопасности видно непосредственно в тексте, без искусственного обрыва.
6. Отправитель учитывает отказ от игровой механики по причинам «не понравилось»
   и «не подходит по самочувствию», включая её варианты для соседних месяцев.
   При заполненном ограничении здоровья исключает двигательные игры, как уже
   делает подборка дня. Это консервативный фильтр, а не медицинская оценка.
7. Переход к старому неполному профилю теперь добавляет отсутствующие поля
   отдельно для этого ребёнка. Чужие сообщения и записи не заимствуются.
8. Отсутствующая или повреждённая дата рождения пропускается при подборе
   поздравления; возраст не угадывается и отправитель не падает на этой записи.
9. Ошибка подключения браузера к push-сервису объясняется по-русски. Успешное
   подключение не показывается до сохранения подписки и настройки.

## Как выбираются подсказки

При каждой проверке пересчитывается полный календарный возраст в часовом поясе
семьи. До двух лет подбор отдельный для каждого месяца, далее окно не превышает
двух соседних месяцев. Приоритет: безопасность, актуальный этап, остальные темы;
при равном приоритете учитываются закрытие возрастного окна и ротация детей.

В пять месяцев есть подготовка к прикорму около шести месяцев, игры общения,
наблюдения и условный уход «если появился первый зуб». Массаж по возрасту
автоматически не назначается. Уведомление не утверждает, что уже появился зуб
или освоен конкретный навык. Возрастная карточка — повод наблюдать, не диагноз.

Основные проверенные основания: [NHS: начало прикорма](https://www.nhs.uk/baby/weaning-and-feeding/babys-first-solid-foods/),
[NHS: сроки прорезывания зубов](https://www.nhs.uk/baby/babys-development/teething/baby-teething-symptoms/).
Календарное окно выбора карточки не отменяет необходимый уход вне этого окна.

## Локальное подключение

Восстановлены только VAPID private/public/subject из зашифрованной резервной
копии от 3 октября. Пара проверена математически и через настоящие подпись VAPID
и шифрование/расшифрование тестового payload. Сетевой транспорт в криптографической
проверке подменён: внешних отправок не было.

Настройки сохранены в отдельном зашифрованном локальном файле под `private/`;
этот каталог исключён из Git. Исходный ключ шифрования локальной базы сохранён.
Конфигурация API выдаёт публичный ключ подписки. Приватные ключи не попадают
в браузер, отчёты, исходники или вывод.

Локальный API запускает один фоновый поток `mama-age-push`. Он проверяет расписание
раз в 60 секунд, соблюдает семейный максимум двух попыток в день. Утром выбирает
новую подходящую тему. Второе напоминание, если включено, относится только к
уже существующей непросмотренной подборке; оно не создаёт новую подборку через ИИ.
Если подходящие темы исчерпаны и готовой подборки нет, уведомление не отправляется.

Процесс работает, пока включён компьютер и запущен локальный API. После сна или
простоя пропущенные часы не догоняются. Это не настройка автозапуска Windows и
не развёртывание на сервере. VM в этой проверке не запускалась.

### Реальная доставка ещё не подтверждена

В существующей локальной базе подписок нет. Тестовый headless-браузер не смог
создать подписку у push-сервиса. Проверено, что в этом случае остаются выключенное
состояние, понятная ошибка и возможность повторить. Успех/отключение интерфейса
дополнительно проверены с явно искусственной подпиской.

Показ уведомления на телефоне, реальная доставка с закрытым браузером и переход
из системного уведомления не подтверждены. Для этого нужно включить уведомления
в обычном поддерживаемом браузере и получить одно тестовое сообщение. Требования
браузеров к разрешениям и безопасному контексту описаны в [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API).
Локальный адрес компьютера не становится доступным на телефоне автоматически.

## Артефакты и воспроизведение

Результаты: `outputs/qa-age-push-20261012/verification-after-fixes.json`,
`browser.json`, `crypto.json`, `service-worker.json`; два мобильных скриншота.
Первоначальный аудит сохранён рядом и помечен как состояние до исправлений.

Из `app/backend/parent-app`: `python -m unittest test_push_delivery test_daily test_guidance test_monthly_content test_age_logic -q`.
Из корня: `node app/scripts/qa-push-service-worker.mjs`, `python app/scripts/qa-push-browser.py`.
Скрипт `qa-push-integrity.py` отдельно сверяет сохранность данных и актуальный
локальный worker; сводные числа тестов/сборки относятся к этому запуску, сам он
не выполняет backend-тесты и сборку повторно.

Python использован из bundled runtime; зависимости браузерной проверки и webpush
установлены отдельно в игнорируемом `private/local-runtime`, не в системный Python.
