# Проверка возрастных push-уведомлений

12.10.2026. Проверена локальная версия; изменения VM не выполнялись.

Это первоначальный аудит до исправлений. Актуальный результат, подключение ключей
и граница проверки реальной доставки: [AGE_PUSH_FIXES_20261012.md](AGE_PUSH_FIXES_20261012.md).

## Продуктовая логика

Каждому профилю соответствует дата рождения. При очередном запуске отправителя
сервис заново считает полный календарный возраст, выбирает актуальные карточки
по нижней и верхней границам возраста и учитывает уже отправленные темы.
Не требуется создавать неизменный сценарий ИИ при регистрации: каталог обновляется,
возраст пересчитывается, устаревшие темы перестают участвовать в новом выборе.
История сохраняется. Это возрастные ориентиры, а не прогноз состояния ребёнка.

Основные файлы: `daily.py`, `daily_job.py`, `age_guidance.py`, `monthly_content.py`,
`parent-sw.js`. `reminders.py` без флага `APP_DAILY_PLANS=1` выбирает старую ветку;
для современного маршрута нужен этот флаг либо прямой запуск `daily_job.py`.

## Фактически найдено

- Для пяти месяцев доступны подготовка к прикорму около шести месяцев, уход
  «если появился первый зуб», ответ на звуки малыша, наблюдения и игры.
- При переходе календарного месяца выбираются другие карточки.
- Поддержаны отдельные профили, семейный предел двух уведомлений в день,
  повторы запусков, ротация детей и открытие нужного профиля/темы.
- Новые лечебные процедуры или массаж по возрасту не назначаются. Напоминания
  о назначениях врача — отдельная задача: необходимы фактическое назначение,
  согласованные дата и время, а не вывод из возраста.

## Что пока не работает как реальная фоновая доставка

В загруженной конфигурации локального API отсутствуют VAPID public/private key
и subject, публичный ключ подписки пуст. Современная ветка отправителя выключена.
Локального процесса `daily_job.py`/`reminders.py` и задания Windows с такими
действиями не обнаружено. Старт существующего локального preview запускает API
и интерфейс, а не возрастной отправитель.

Значит, карточки внутри сайта работают, но заявлять, что уведомления уже
самостоятельно приходят при закрытом браузере, нельзя. Доставка на реальное
устройство не тестировалась; подписки и реальные сообщения не отправлялись.

Перед активацией нужны секретно сохранённые ключи VAPID, разрешение пользователя,
подписка браузера, фоновое расписание и проверка на реальном устройстве. Локальный
runtime не следует незаметно запускать с генерацией планов всех аккаунтов:
`daily_job.run` генерирует подборки до проверки push. Расписание должно учитывать
существующие лимиты и бюджет. Этот аудит не менял настройки и не запускал платную ИИ-генерацию.

## Медицинские границы

- [NHS: прорезывание зубов](https://www.nhs.uk/baby/babys-development/teething/baby-teething-symptoms/): сроки существенно различаются. Уведомление не сообщает,
  что у конкретного ребёнка обязательно начались зубы, и не объясняет ими любую температуру.
- [CDC: ориентиры к шести месяцам](https://www.cdc.gov/act-early/milestones/6-months.html): ориентиры для наблюдения, не диагноз и не замена валидированному скринингу.
- В соответствии с CONTENT_RULES.md возраст не доказывает навык; лечебный массаж
  не назначается календарём. Срочная информация не прячется ради открытия сайта.
