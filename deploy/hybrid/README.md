## Адреса и приватность

- `https://app.ВАШ-ДОМЕН` — интерфейс Cloudflare Pages.
- `https://api.ВАШ-ДОМЕН/api` — прямое подключение браузера к российскому VPS.
- Запись `api` — **DNS only**; Cloudflare proxy, Tunnel, Worker proxy выключены.
- Поддомены одного принадлежащего владельцу домена нужны для совместимых
  с Safari cookies: host-only, HttpOnly, Secure, SameSite=Lax.
- `APP_ORIGINS` содержит только точный HTTPS-адрес интерфейса. Никаких `*`,
  автоматического разрешения preview-поддоменов или токенов в localStorage.
- Панель владельца, bridge и n8n слушают только `127.0.0.1`. Доступ — SSH-туннель.
- Cloudflare получает публичные файлы, но не тело чата или профиль через API.
  Cloudflare всё равно обрабатывает сетевые метаданные посетителей интерфейса.
  Другие обработчики, включая поставщика ИИ и push-сервисы, требуют своей
  проверки и отражения в политике. Хранение в РФ не отменяет эти обязанности.

Сервис Cloudflare сообщал о замедлении доступа из РФ в июне 2025; это не
результат сегодняшнего измерения. Перед переключением проверить реальный
адрес у тестировщиков через мобильную сеть и домашний интернет.
[Сообщение поставщика](https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/).

## Уже подготовленные инструменты

`prepare.py backup`: SQLite backup API для шести баз, контроль целостности,
зашифрованный архив и проверка фактического восстановления всех строк.
Исходные базы открываются read-only. Ключ архива — существующий
`private/n8n/backup.key`; сохраняется отдельно у владельца.

`prepare.py verify-preservation FOLDER`: сверка исходных строк аккаунтов,
профилей/переписки и файла теста из 50 вопросов. Мониторинговые журналы могут
пополняться во время работы; они не объявляются неизменными.

`prepare.py stage --domain DOMAIN --node NODE --output FOLDER`:
сборка Vite в отдельный каталог, абсолютный HTTPS API, заголовки Pages,
проверка разрешённых файлов и отсутствия известных приватных ключей.
`--test` разрешает искусственный домен, но **не создаёт архив для публикации**.
Старый `app/dist` и локальный `public/app-config.json` не изменяются.

`prepare.py source --output FILE.tar.gz`: исходники основного `app/`, правила,
шаблоны и исходный тест из 50 вопросов. Исключены секреты, базы, private,
node_modules, кеши и обе 3D-версии. Этот пакет предназначен для российского
сервера, **не для загрузки на Cloudflare**.

`render-server.py --domain DOMAIN --output private/NEW_FOLDER`:
закрытые env-файлы, nginx и systemd для Linux. Сохраняет ключи базы/n8n,
настройки ИИ, VAPID, бюджет и политику; заменяет только пути и адреса.
Нельзя выводить содержимое env в терминал, чат или отправлять в GitHub.

`restore-data.py --archive FILE --key-file FILE`: проверяет hashes, целостность
и число строк каждой из шести баз, не записывая файлы. `--destination NEW_FOLDER`
восстанавливает только в новый каталог; существующие данные не перезаписывает.
Проверяет allowlist архива, отсутствие traversal/symlink и ограничение размера.

## Порядок переноса после одобрения расходов

1. Владелец оформляет VPS в РФ и выбранный домен; при регистрации пароль,
   личные документы и условия оформляет сам. Подтвердить финальную цену и
   документы обработки персональных данных до загрузки реальных записей.
2. Проверить SSH, ОС, свободные RAM/диск, исходящую почту и доступ к ИИ.
   Создать отдельного пользователя `mama`; публично открыть только SSH, 80, 443.
3. Установить Python с venv, nginx, certbot, совместимый Node 22/24 и n8n
   **2.42.7**, совпадающий с локальной версией. Зависимости backend — существующий
   `requirements.txt`. Никаких платных панелей, балансировщика или нового PostgreSQL.
4. Развернуть исходники в `/srv/mama/app`, Python в `/srv/mama/venv`, n8n
   в `/srv/mama/n8n-runtime`. Установку пакетов выполнить до включения служб.
5. Согласовать короткую паузу записей на текущем источнике истины; сделать
   **новую финальную копию**. Подготовленная сейчас копия не включает будущие записи.
   Не объединять вслепую базу старой VM, Cloudflare Durable Objects и локальную:
   возможны разные версии и повторы. Сверить ревизии до решения о слиянии.
6. Передать зашифрованный архив и ключ по SSH только на выбранный российский
   сервер. Проверить hash перед распаковкой. Распаковать строго в новый каталог,
   отвергать абсолютные пути, `..`, symlink/hardlink. Восстановить `data/` в
   `/srv/mama/data`; пользователь `mama`, каталоги 700, файлы 600.
7. Разместить закрытые env-файлы в `/etc/mama`, root:mama, права 640;
   папка 750. Проверить, что APP_LOCAL=0, оригинальные ключи и базы не заменены,
   CORS точный, cookies Secure/Lax, бюджеты не сброшены.
8. Стартовать API, operations, bridge, n8n через подготовленные systemd units.
   После рестарта сверить целостность/число строк и доступность loopback-служб.
   n8n запускать с оригинальной базой и encryptionKey, не импортировать поверх
   неё новую копию workflow с новыми идентификаторами.
9. Настроить A-запись `api`, DNS only; получить TLS через HTTP-only ACME
   конфигурацию. Только после выпуска сертификата включить `nginx-api.conf`.
   Перед reload обязательно `nginx -t`. Проверить HTTPS, CORS, cookies,
   запрещённый Origin, недоступность внутренних портов извне.
10. Собрать **реальный** frontend с окончательным доменом. Проверить API отдельно
    на искусственном аккаунте. В Cloudflare Pages Direct Upload передать только
    `cloudflare-static.zip`/папку `public` этой сборки. Не подключать весь GitHub
    к публикации, Worker, Durable Objects или R2 с данными пользователей.
11. Подключить `app` как custom domain Pages. Проверить вход/выход/перезагрузку,
    последнее сообщение, переключение детей, исправление отметок и графики,
    избранное, лимиты/ошибки ИИ, доступ к первой помощи при недоступном API.
12. Push-подписки привязаны к origin: старые записи сохранить, на новом домене
    пользователю нужно добровольно включить уведомления заново. Проверить
    доставку на согласованном тестовом устройстве, максимум два напоминания.
13. Включить timer напоминаний после проверки согласий/таймзон/идемпотентности.
    Проверить n8n анализ отзывов с синтетическими данными и закрытыми admin-портами.
14. Проверить резервную копию после запуска и восстановление в отдельном каталоге.
    Переключить публичную ссылку только после smoke-test. Старый сервис сохранять
    до подтверждения переноса, чтобы оставался путь возврата.

## Что нельзя объявлять готовым заранее

- SMTP сейчас не настроен; настоящая доставка email ещё не проверена.
- Приём оплаты сейчас выключен; эквайринг/чеки/юридические реквизиты не заменяются
  переносом. Настройка платного тарифа сама по себе не означает приём денег.
- TLS, Safari/iPhone, публичная доступность из РФ, реальные push и перезагрузка
  нового VPS проверяются **после** появления сервера и домена.
- Копия локальных баз не является доказательством совпадения с выключенной старой
  VM. Последняя база VM в этой операции ещё не прочитана.
- Число зарегистрированных пользователей не равно одновременной нагрузке;
  нагрузочная проверка нового сервера ещё не проводилась.

## Возврат

Не удалять старую систему или её базу. Сохранять версию статических файлов и
конфигурацию DNS до переключения. После появления новых записей на VPS нельзя
возвращаться к старой базе без выгрузки этих изменений. Во время восстановления
остановить писателей API/n8n/timer; проверить ключи, hash и SQLite integrity.
Нельзя сбрасывать лимиты ИИ или подменять исходную переписку копией тестов.
