# Запуск тестовой платформы на «Поехали»

## Состояние

Frontend готов для существующего Vite-хостинга. Гостевое демо `/demo` и памятки работают без сервера. Настоящие регистрация, вход, восстановление, профиль и сохранение данных используют сервер. **Публикация файлов в GitHub сама по себе не создаёт базу и облачные функции.** Пустой `public/app-config.json` намеренно не имитирует регистрацию.

Для одной VM в Yandex Cloud можно явно задать `APP_DB_DRIVER=sqlite`: база SQLite с WAL хранится на постоянном диске, а профиль и переписка шифруются `APP_DATA_KEY`. Это вариант для одного небольшого сервера; при росте нагрузки перенесите базу в Managed PostgreSQL. В облаке не включайте `APP_LOCAL`.

## Однократное подключение в проекте «Поехали»

1. Включить «Ядро»: PostgreSQL и Python Cloud Function для `backend/parent-app/index.py`, обработчик `index.handler`, зависимости из `requirements.txt`. Включить передачу заголовков Cookie/Origin/Set-Cookie; CORS обрабатывает функция.
2. Создать таблицы из `backend/parent-app/schema.sql` отдельной миграцией. Не запускать инициализацию при каждом запросе. Выделить приложению собственную схему/базу; настроить search_path подключения, если «Поехали» выделяет схему.
3. Серверные секреты: `DATABASE_URL` (SSL), `APP_DATA_KEY` (Fernet key, 32 случайных байта в urlsafe base64), `APP_ORIGINS` (точные HTTPS origin сайта и нужного preview через запятую). `APP_LOCAL` в облаке НЕ задавать. Не отправлять секреты в публичный GitHub.
4. Прописать выданный платформой HTTPS URL функции в `public/app-config.json` → `apiUrl`. Альтернатива для сборки: `VITE_APP_API_URL`; это только публичный адрес, не ключ. Функция получает POST с JSON `action`.
5. Предпочтительно проксировать функцию под `/api` того же домена: cookie работает и в браузерах с запретом сторонних cookies. Для отдельного домена функции нужен `APP_COOKIE_CROSS_SITE=1` (Secure; SameSite=None), но Safari и другие браузеры могут всё равно блокировать cookie. В таком случае нужен same-origin proxy, а не хранение токена в localStorage.
6. Проверить `/account`: регистрация → сохранить код восстановления → профиль → выход → вход. На другом аккаунте не должно быть чужих данных. Протестировать на телефоне по реальному домену. SPA-хостинг должен возвращать index.html для `/account`, `/cabinet`, `/demo`, `/privacy`.

## Чат-помощник

Ключ CheapAI хранится только в серверном секрете `CHEAPAI_API_KEY` (для совместимости сервер также понимает старое имя `CHEAP_AI_API_KEY`). Простая модель задаётся секретом `CHEAPAI_SIMPLE_MODEL`; безопасное значение по умолчанию — `gpt-5.6-luna`. Не помещать ключ в `VITE_*`, `app-config.json`, frontend или GitHub.

Для Yandex Cloud AI Studio сервер поддерживает `YANDEX_FOLDER_ID`, `YANDEX_API_KEY` и `YANDEX_MODEL` (по умолчанию `yandexgpt/latest`). Предпочтительно подключить к VM отдельный service account только с ролью `ai.languageModels.user`, задать `YANDEX_USE_METADATA_IAM=1` и не хранить API-ключ на VM. Краткоживущий IAM-токен берётся из metadata service. Запросы идут на OpenAI-совместимый API AI Studio с `x-data-logging-enabled: false`.

Сервер передаёт модели этап, точный возраст по дате рождения, тип кормления, сведения о сне и выбранные темы. Он не передаёт email и не разрешает модели ставить диагнозы, назначать лечение или рассчитывать дозировки. `action=config` показывает, настроен ли чат, не раскрывая ключ; `action=health` проверяет соединение с базой и ключ шифрования.

## Push

Для push нужны ключи VAPID (серверный `VAPID_PRIVATE_KEY`, публичный `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT=mailto:<контакт владельца>`). Публичный ключ сервер отдаёт через action `config`.

Развернуть `reminders.handler` из того же каталога отдельной функцией с теми же DB/шифровальными секретами. Добавить `REMINDER_JOB_TOKEN` (минимум 32 случайных символа). Настроить защищённый ежедневный POST из планировщика в 09:00 Europe/Moscow, заголовок `X-Task-Token` — значение секрета. Не помещать секрет в браузер. Для большой аудитории потребуется очередь и разбиение задачи; этот последовательный обработчик предназначен для небольшого теста.

Доставка по текущему этапу; нет ежедневных новых рекомендаций. Повтор — только по выбору пользователя, до чтения/скрытия. Дедупликация для устройства хранится в PostgreSQL. Push содержит только нейтральное уведомление. В редком случае остановки функции после резервирования доставки до отправки уведомление может пропасть; эту схему нужно дополнить очередью и lease перед масштабированием. Внутренние карточки от этого не зависят. Web Push зависит от браузера, не гарантирует точное время и не используется для неотложных действий.

## Данные и ограничения теста

Пароли: PBKDF2-SHA256 с индивидуальной солью; сессии — случайные opaque cookies HttpOnly; в БД хранится только хеш токена. Профиль/переписка и push-подписки шифруются Fernet. Секрет шифрования необходимо хранить и резервировать отдельно от БД: при его потере данные не читаются. Email не зашифрован, используется для входа; email verification и почтовой службы нет. Восстановление — одноразовый код, выдаваемый при регистрации/восстановлении. При утрате пароля и кода автоматического восстановления нет.

Для теста использовать вымышленные медицинские данные. До публичного сбора реальных данных владелец должен определить контакты оператора, сроки хранения/резервных копий, согласия и размещение, дополнить `/privacy`. Вебвизор и сторонние runtime-трекеры удалены из index.html; отдельно проверить, не добавляет ли хостинг трекеры при публикации. Медицинская экспертиза контента не проведена; нет диагностики, дозировок и индивидуальных схем. До такой экспертизы чат предназначен только для бытовых вопросов и поддержки родителей. Оплаты нет.

## Проверка кода

Frontend: `npm ci`, `npm run build`, `npx tsc --noEmit`.

Backend: `python -m unittest discover -s backend/parent-app -p 'test_*.py'`. Тесты используют временную SQLite и настоящие хеширование/шифрование, проверяют регистрацию, изоляцию аккаунтов, cookies, восстановление, лимиты, валидацию и дедупликацию. Обязателен дополнительный smoke-test с PostgreSQL и облачными cookies на «Поехали».

Для локального сервера: `python backend/parent-app/local_server.py`. Требуется cryptography, переменные APP_DATA_KEY, APP_SQLITE_PATH (вне git), APP_ORIGINS=http://localhost:5173; локальный сервер выставляет APP_LOCAL=1. Vite proxy `/api` уже настроен на 127.0.0.1:8787; apiUrl можно задать `/api` для локального теста.
